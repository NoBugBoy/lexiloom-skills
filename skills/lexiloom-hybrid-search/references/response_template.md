# LexiLoom 混合检索响应指南

本文件是**按问题复杂度使用的指南**，不是每次回答都必须照搬的固定模板。简单问题直接回答即可；只有需要把本地实现与知识库规则进行对照时，才使用完整结构。

## 1. 默认结构

### 结论
用 1–3 句话回答用户问题。明确区分已验证事实、合理推断和待确认项。

### 证据
- **代码证据**：仅填写实际检索到的文件、类、方法、行号和代码行为。
- **知识库证据**：仅填写真实返回的文档标题、文档 ID、切片内容及可用元数据。
- 不相关的一类证据可以省略；没有结果时写明“本次检索未找到足够证据”，不能推断为不存在。

### 差异与建议（需要时）
| 维度 | 知识库要求 | 当前代码证据 | 结论 |
|---|---|---|---|
| 业务规则 / 参数 / 异常处理 | 具体且有来源 | 具体且有来源 | 一致 / 冲突 / 证据不足 / 待人工确认 |

每一项结论都必须有相应证据。不要为了填满表格而编造规则或实现。

## 2. 代码实现问题

建议包含：
- 核心文件、类和方法；如工具提供了可靠行号，则附行号。
- 调用关系：只描述已经追踪或有代码支持的链路。
- 关键代码片段：保持简短，保留足够上下文。
- 若只搜索到符号名而未检查实现，应明确说明证据有限。

## 3. 知识库规则问题

建议包含：
- 文档标题和文档 ID（如果接口返回）。
- 规则摘要与必要的简短原文摘录。
- 检索得分（如果展示）只作为搜索排序信号，不写成“92% 正确”或类似表述。
- 没有真实 URL 时不要自行拼接文档链接。

## 4. 代码与规范对齐

将发现归类为以下之一：

- **一致**：规范与代码均有明确证据且相符。
- **明确冲突**：规范和代码的实际行为有直接冲突证据。
- **代码侧证据不足**：找到规范，但未能确认实现。
- **知识库侧证据不足**：找到实现，但未检索到明确规范。
- **待人工确认**：证据含糊、规则有多种解释或需要运行时验证。

不要将“未搜索到”直接判定为“不存在”或“不符合”。

## 5. 建议质量

建议应具体、可执行，并与发现的问题对应。例如补充某个边界测试、确认某条业务规则、更新对应文档。没有证据证明测试已存在时，不要声称测试已经覆盖；没有运行测试时，不要声称测试通过。

## 6. 禁止事项

- 不编造绝对路径、`file://` 链接、行号、URL、文档标题、调用链或测试结果。
- 不虚构匹配分数、精度或统计数据。
- 不将推断伪装成文档原文。
- 不输出 API Key、环境文件内容或其他凭证。
